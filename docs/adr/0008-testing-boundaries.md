# Границы тестирования: три шва

Тесты ведём на трёх швах: (1) доменная логика бронирования на backend без HTTP — генерация слотов, пересечения `[start, end)`, границы окна, рабочие часы; (2) HTTP API-контракт на Spring Boot со случайным портом — эндпоинты и ошибки `409`/`422`; (3) фронтенд на Vitest + Testing Library — рендер и переходы. Сгенерированный код не тестируем (не редактируется руками, покрыт контрактом). E2E (Playwright) добавлен позже, на этапе упаковки (см. job'ы `E2E` и `Docker` в `.github/workflows/ci.yml`); в рамках первых тикетов он был вне границ.

Причина: доменные инварианты — самое рискованное место и дешевле всего ловятся юнитами; контракт проверяется на HTTP-шве; UI — на фронтенде. Отвергнуто: только e2e (дорого и хрупко) и тестирование сгенерированных артефактов (бессмысленно, перезаписываются).
