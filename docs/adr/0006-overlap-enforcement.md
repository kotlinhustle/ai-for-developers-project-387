# Запрет наложений: exclusion constraint в Postgres

Чтобы две брони не легли на одно время даже при гонках, источник истины — БД: Postgres exclusion constraint `EXCLUDE USING gist (tstzrange("start", "end", '[)') WITH &&)` на таблице броней. Приложение дополнительно делает предварительную проверку пересечения для дружелюбного ответа, а нарушение констрейнта на гонке отдаёт `409 Conflict`.

Причина: интервальное пересечение не выражается обычным unique-констрейнтом; exclusion constraint — самый надёжный способ и не зависит от логики приложения. Это фиксирует СУБД — **Postgres**. Отвергнуто: только транзакционная блокировка без констрейнта (слабее, легче ошибиться) и уникальный индекс по времени начала (не ловит частичные наложения).

Оговорка: без `DB_URL` приложение работает на in-memory H2, где этого констрейнта нет (см. ADR-0009); ограничение действует на Postgres-пути (деплой и работа с `DB_URL`).
